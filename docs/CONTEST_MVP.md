# 比赛前 Aegis 临时影响循环（Pi 编码任务书）

状态：历史比赛实现任务书，部分方案已被用户撤回，不能作为当前整体架构的替代规格。用户明确要求遵循原架构；Observer、图板、RAM、短会话、Oracle、经验反馈等职责不能因时间紧被自行删除。本文中的“移除 Observer”“仅用提示卡替代影响循环”“完整链路留到赛后”等限制不再作为架构决定执行。当前已确认决定见 `ARCHITECTURE_DECISIONS.md` 开头；代码尚未据此调整。

用户要求不重构内嵌 Pi；实现代码只由 Pi 中转模型 `relay/deepseek-v4.1-flash` 编写，审计者只检查、测试和写文档。

## 必须在比赛前实现的最小链

```text
用户授权的比赛任务 + 显式观察/用户选定的上下文
  -> 受控候选卡（由人工整理或比赛前验证，不从日志自发晋升）
  -> 在 Pi 请求开始时做精确匹配、只注入最多 1-2 个短提示
  -> Pi 正常规划和用原有工具执行
  -> 记录注入/拒绝/工具次数/人为或平台给出的结果
  -> 下次检索/对照复盘（只提候选，不写 active）
```

用户要的是对模型的**判断有影响**，不是原型 `fixture.unlock` 对工具执行的捷径。指导模型时明确分开 verified / candidate / unknown，不得让经验覆盖用户要求、授权和真实环境证据；不命中就什么也不注入。无预置合格卡时，提示可能为零——要诚实报告，而不是制造“经验命中”。

## 开发范围

- 可新增 Aegis-owned Pi 扩展（TypeScript）、一个小的 source-only 比赛启动入口、用于自测的只读样例卡和离线 smoke tests；必要的数据处理可用 Python + `uv`。本任务不需 C，也不需装新依赖。
- **不要修改** `Pi_Agent_base/pi/` 源码、原始 `run-pi.sh`、现有 `config/agent/{auth.json,models.json,settings.json}` 和已有根目录 Python 删除状态。当前 bundle 缺失；比赛入口必须使用 `Pi_Agent_base/pi/pi-test.sh` 源码路径；不可假装现有 bundle 启动器能跑。
- 不自动加载项目扩展/MCP/codemode、不用内嵌工作树中的全局配置；显式 `PI_CODING_AGENT_DIR`, `PI_CODING_AGENT_SESSION_DIR`, `PI_SERVER_DIR` 下隔离；固定 `relay/deepseek-v4.1-flash`。不要输出凭据或调用真实比赛网络。
- 不做通用知识库、自动判题、跨题 active 晋升、爆破策略、硬安全沙箱或复杂多会话调度；现有 `fixture` 原型不可冒充比赛记忆。
- 比赛期间保留 Pi 原有常用工具 `read,bash,edit,write`，不要将 prompt/工具钩子说成系统权限隔离。若本次加入操作约束，只拦明确越界的文件删除等高危动作，不靠笼统正则判定所有 `bash` 安全；认不准时按人类确认/独立沙箱处理。用户明确要求避免无根据的防御性代码堆叠。

## 提示卡契约（最小、可审计、默认关闭）

可采用小型 JSON 文件（或手动指定文件夹内的 Markdown 卡但要可机械解析），只从明确指定的路径加载，解析失败不可扩展作用域：

- `id`，`revision`，`title`，`status`（`verified`/`candidate`）；`source_refs`/出处和验证状态；
- `scope`（本次比赛/任务类别/环境必要条件；不知道不当通配符）；`when` 明确的短条件；
- `hint`（最多几行，内容为建议观察/已证实路径，非命令）；`expect` 或“需要验证什么”；
- 如选择人工强制 `hint`，必须显示“人工选择/未经此题验证”，不能转为硬事实或自动动作。

自动命中只能来自用户/外部确定性观测，不能仅把模型自己的说法当成事实；默认 `candidate` 仅在明确人工选择时给 hint，缺条件/冲突/卡源不明不自动注入。不要把 WP 文本注入高优先级系统指令位置。`verified` 仅指有可信来源，但跨题不等于这题已满足前提。比赛前可以用人工选择的短卡验证流程；不要预置看似正确却未证实的利用技法。

## Pi 最薄接入点

- `before_agent_start`：对有界卡集合按显式 scope/when 匹配，更新单个 prompt section 或随用户输入注入**低信任度、可辨认**的简短提示，注入来源和当前条件/未知写明，绝不能把未经验证的外部 WP 变成 ROM。
- 可使用 `registerCommand`（例如 `/aegis` 子命令）供用户在赛中**手动**查看匹配原因、选一条候选、取消提示/切换实验组、记录人工结果。只要一个简单可靠入口，非 TUI/print 模式不应阻塞；命令与 Pi 扩展 API 需以当前 `extensions/types.ts` 为准。
- `tool_call` / `tool_result` / `agent_settled`：只记录必要元数据、耗时和 status hint（不是任务成功），结果由人/平台单独记录。Observer 现有版本 `enqueue()` 会吞写失败且恢复时 hash chain 不衔接，不得宣称它满足可靠审计；比赛 MVP 可写独立简易元数据日志并验证跨重启一致性，失败时要明显提示人类。不把旗帜、密钥或原始工具输出写进新的分析日志。
- Pi session JSONL 是模型上下文与调试材料，不是 Outcome；比赛 WP 和 flag 可能在文件中，放在 `Pi_Agent_base/runtime` 或其他指定权限受限目录，提醒用户不要公开或直接上传。

## 比赛实际检验，而不是口头自证

- 启动参数有明确 `off`（只记录、不注入）与 `hint`（最多两条短提示）。保持相同基础 ROM、模型、工具和预算；每道题开新会话，**不在同一题中更换实验组**；按任务/难度、时间/工具次数/结局记录，若只有几题，只做有因果线索的探索性对照，不声称统计显著。
- 输出一张简单赛后表：题目匿名 ID、实验组、注入卡 ID/revision、命中前提证据、首次行动、工具次数、token/耗时若可用、平台/人工结果 success/failure/unknown、是否误触发/负迁移。不能从“模型说 solved”推断 success。不同难度的题不直接比较绝对耗时。
- 有经验却帮助错误时能够临时关闭卡、回退到 `off`；下一题不自动当失败禁令，先核对当前前置条件、环境与外部结果。

## 必须先测试

1. 无卡/未匹配/未知条件 -> 无注入；手动候选提示明确标为未验证，最多 2 条；禁用模式无注入。
2. Pi extension 通过真实 Pi faux-provider session 或 mock hooks 测试确实改动下一请求上下文；Observer/旧 fixture smoke 不回归。优先不用付费模型做测试；真实中转 smoke 经明确限额才执行。
3. 新日志无原始 flag/凭据、能关联 Pi session 与 hint 决策；日志写失败不静默误报正常。
4. 源码启动入口 `--help` 能启动；能显式选择 `off`/`hint`；断言嵌入 Pi 源码与凭据配置未被意外修改。Observer 必须保留其事件采集职责；其 ROM/RAM 注入与 Router 投影的组合冲突应修复兼容性，不能通过删除 Observer 规避。加载方式和工具集的具体调整需遵循已确认契约，完整组合必须用真实 Pi 请求边界测试。当前只加载 contest 的代码属于待调整实现，不代表已批准架构。

## 时间排序

P0：source-only 启动成功、开关 A/B、受控提示/可撤销、元数据采集、离线集成测试。
P1：比赛任务第一条**经人工审阅的**卡 + 平台判定手录和赛后表。
P2：停机恢复、自动检索、案例/失败编译、完整 `Episode/Outcome/Experience` 晋升门，赛后再做。与 P0 分开标记，不能宣称已实现。

## 追加：用户确定的核心验收（数据与每日复盘）

比赛的主要任务是**收集可信数据、每天复盘并修正 Aegis 的设计假设**，不是赛中自动宣布学习成功。必须在可用 Pi 工具链的前提下满足：

1. **每题留完整可归档会话**：不要默认 `--no-session`；每次新题用明确的匿名 task_id 和新会话，始终保留原始 Pi session JSONL 和 Aegis 元数据日志的关联。Session 可能含 flag、题目内容和凭据，存放在被忽略的限制权限目录，不传到模型以外的外部服务，不复制到 `docs/` 或公开仓库；不要默认收集完整敏感工具输出到新增日志。
2. **影响可识别**：每个实验组固定 `off`/`hint`；记录启动时间、模型/版本、任务类别、环境标签、card ID/revision、是否自动/人工匹配、何种可检验前提、prompt section 是否真的注入；工具名/调用 ID/错误标记/基本计数，日志写入失败必须被看见。不能只看模型自报是否采用提示；记录第一次关键行动或人工复盘标注是否实际改变了决策。
3. **结果独立输入**：外部平台验收（如题目计分）或用户明确确认的结果另外记录为 `success` / `failure` / `unknown`（缺失默认 unknown），带来源与时间；没有可靠来源不得从 `agent_settled`、退出码或自述提升结果。不要把 flag 明文写进结果文件；可以记录非敏感证据引用/摘要。
4. **每天一份确定性复盘**：从当日日志、会话统计和人工/平台判定生成 CSV/Markdown 或 JSON+Markdown 的只读日报，按 task_id/session_id 去重，列出组别、注入/使用、工具次数、预算/时间若可用、独立结果、未知与异常、遗漏字段。额外列出“今天 Aegis 的误匹配、漏匹配、负迁移、事件日志失败、observer 丢事件与尚无判定”的具体可核查项目；建议次日调整（候选建议，不自动写入经验库）。只有几题时不要声称统计有效性，说明题目难度与时间不可比。
5. **运行前自测**：`--help`、`--off` 默认隔离、`--hint` 有已验证/人工候选卡才注入；用 Pi faux provider 或 hook mock 验证本轮注入和关掉后撤回；测试磁盘写失败时不产生“已成功记录/已安全注入”的虚假陈述。不要让测试输出与实际状态相反。

比赛用的真实自动提示须先经人逐张审查；样例卡只供离线 smoke，不能仅改类别标签就作为比赛有效规则。赛后每次规则改动附关联的题目与失败证据，不静默重写历史运行日志。

## 审计追加：数据要先可靠，才有资格分析效果

- `run.sh` 比赛模式要求每道题提供匿名 `AEGIS_CONTEST_TASK_ID`，拒绝空值/含路径的值；每题新 session（但不自动删除历史），展示 task_id 与组别，不输出密钥；禁止透传 `--no-session`、`--session-dir`、`--model`、`--provider`、`--no-extensions`、`--extension`、`--no-mcp` 等改变对照条件的参数（或仅允许经文档明确的参数集合）。否则报告应明确该题实验配置失控，不纳入 A/B。source-only Pi 入口 `--no-approve` 应防止项目内陌生扩展与 MCP 加载；是否启用 `--no-context-files` 应说明：它改变解题工作流，必须对 off/hint 两组一致。
- Aegis contest 扩展的 `MetaLog` 写失败时，**不能声称提示已安全记录**；自动提示默认不注入、通知人类该次数据失效，持久化失败写入明确诊断（stderr/告警）而非只在有 UI 时悄悄继续。可保留正常的 Pi 解题工具，但该 episode 不能进入有效对照。日志失败后队列可以恢复，不可以静默停止采集整场比赛。
- 不允许“结果字段缺失或来源随便写字符串就 independent=true”。`success/failure` 需要明确平台判定或人工**独立核对**并提供短、非敏感证据引用；缺失为 `unknown`。日志可追加更正记录，日报显示来源、冲突与缺失，不能悄悄以最后一行抹掉较早事实。人工只转述模型的 solved 不满足独立性。
- **不要猜 Pi JSONL 工具计数**：扩展自己的 `tool_call` 与 `tool_result` 元数据是权威活动计数；Pi session JSONL 的助理 `message.content[].type=toolCall` 与 `toolResult` 的 role 只用于旁路交叉检查（当前 `docs/session-format.md`），若不一致显示 `count_mismatch`。多个 session/同题和跨日补结果必须保持可追踪，日报有“无独立结果/日志错误/配置不一致/提示误触发/可能负迁移”的待人审字段。有限任务只报事实，不作统计因果结论。
- 增加一条使用 Pi SDK faux provider 的**真实会话**离线验收：同一可控提示卡的 off/hint 两组进入 Pi 请求上下文时确有差异；清除/不匹配后下一请求不保留过期提示；模型输出如何变化并非自动判断成功，工具调用元数据与 session_id/task_id 可关联。

以上属于比赛前修数据采集，不扩展成跨题学习器，也不修改现有 `Pi_Agent_base/pi/`。

完成时给出：文件清单、最简启动命令、明确的安全边界、离线测试结果、不能证明的内容。无 Git 提交、无非预期覆盖、无真实模型/CTF 网络操作。
