# 图板与 seed 的首轮 CTF 验证

状态：本文件保留首轮设计与离线诊断。后续已完成公开题下载和真实先导，因 provider 错误未形成有效四组比较；实际结果见 [先导报告](BOARD_SEED_CTF_PILOT_RESULT.md)。工具注册产品化暂缓，使用已有 CLI 能力和本地任务副本。

本次检查基线为主仓库 `dc3d3fa`。本文件中的难度信号、实验模式与指标为待实施实验设计，不代表已有自动难题分类器、分支搜索器或完整实验开关。

## 1. 当前图板何时工作

Observer 在运行中持续收集事件，Board/RuntimeState 从已提交事件投影。每个 provider 请求前，`context_with_system` 重建有界 RAM，包括同一 prompt 内工具调用后的请求。没有“先判定难题才开启图板”的步骤。

模型的 Claim/Intent/Candidate 仍依赖显式 `aegis_propose`，当前 guidelines 提醒在假设、子目标或路线变化时记录，普通助手正文不会自动成为图板提案。候选 `when/do/expect` 与 source refs 可进入图板/RAM；来源关联不等于证明。

子目标/验证结束、路线切换、上下文临近预算时，模型可以请求 `aegis_switch_session`；Host 在工具 settled、日志持久化、无未决效果并满足预算/权限时执行。交互式 `/aegis switch`/Host helper 与 C6 自动轮换是不同入口，不能混称全局自动。

seed 自动召回在每次 `before_agent_start` 基于当前用户消息运行；模型可根据后续消息、观察与图板调用 `aegis_knowledge` 重选。RAM 每次请求更新不代表每次都会启动一个独立模型做知识选择。

## 2. 本次已运行的验证

从仓库根运行：

```sh
node --import ./Pi_Agent_base/pi/packages/coding-agent/src/experimental/source-resolver.ts Pi_Agent_base/tests/aegis-knowledge-sdk.mjs
node --import ./Pi_Agent_base/pi/packages/coding-agent/src/experimental/source-resolver.ts Pi_Agent_base/tests/aegis-ram-reaudit-sdk.mjs
node Pi_Agent_base/runtime/dev/knowledge-efficacy/recall-audit.mjs
```

前两条退出码均为 0：知识自动进入首请求、模型查询后下一请求更新、候选/关联投影及同 Episode 新 Session 恢复通过；RAM 交接复验 7 项通过。均为真实 SDK + faux provider，不证明真实模型解题准确率。

第三条为 ignored 验证脚本，退出码 0 只表示诊断完成，不表示检索断言全通过。证据保存在 `Pi_Agent_base/runtime/dev/knowledge-efficacy/recall-results.json` 和 `recall-output.log`。脚本使用当前 ignored CTF Wiki seed，因知识内容不纳管，需复制同一知识目录才能重现相同语料。

预先给出六个技术方向、两个负例，对症状查询与明确技术查询分别取 top-3：

| 样例 | 症状查询 | 明确技术查询 | 诊断 |
| --- | --- | --- | --- |
| printf 格式串作为用户输入 | 未命中格式串方向，选到 ELF 结构 | 命中格式化字符串 | 一般环境词挤掉关键症状 |
| 释放后索引仍可读写 | 未命中 UAF，选到 malloc/free 实现 | 命中 Use After Free | 机制实现与漏洞条件混淆 |
| RSA e=3、短明文、无填充 | 命中 RSA 大类但选到选择明密文攻击；严格判错 | 命中公钥指数攻击 | 大类命中不足以算方向正确 |
| 页面根据 SQL 条件真假变化 | 命中 SQL 文档 | 命中 SQL 文档，但前列仍是注释语法 | 段落适用性仍不足 |
| 服务端代请求 URL/访问内部服务 | 未命中 SSRF，选到内核用户访问资料 | 命中 SSRF | 症状到概念的召回不足 |
| dispatcher/状态变量/基本块切换 | 命中控制流平坦化 | 命中控制流平坦化，亦有 Reference 段落 | 方向命中，不保证片段有用 |
| 春游邀请函 | 误召回内核模块 | 不适用 | 缺少可靠的不相关拒绝 |
| 无意义未知主题 | 无召回 | 不适用 | 正常负例 |

症状查询按文档/方向标准为 3/8；明确技术查询文档/方向为 6/6。明确查询由评估者手写，不能冒充 LLM 自主识别成功，也不是提高检索算法后的结果。最初按 RSA 大类算 4/8，收紧到具体攻击方向后为 3/8；本表沿用严格标准。SQL 的具体段落不适用未被宽松文档命中掩盖。

逐查询本地检索耗时约数百毫秒，仅是检索时延；不代表解题节时。当前证据不足以支持 seed 提高准确率或降低总耗时，错误召回可能增加偏航成本。

## 3. 如何判定适合验证图板的难题

基础日志始终开启，不依赖难度判定。难度是相对于固定模型、工具与预算的实测属性，平台“hard”标签只用于初筛。

首轮选题应同时有：

- 至少两三个有先后依赖的可验收阶段，关键中间值需要跨步骤保存。
- 两条以上合理假设或探索分支，存在可以排除某条路径的观察。
- 本地可重置、环境稳定、成功可独立校验，已有 CLI 足以完成。
- 基线模型有部分进展但并非次次秒解或次次完全无进展；先导运行用于校准，正式样本仍保留全部结果。

运行中可建议加强结构化记录的信号：多条未决假设竞争、同一假设重复尝试且无新证据、环境/版本使旧结论失效、长工具反馈挤占上下文、切换子目标/Session 前。模型可以提出判断，计数/上下文大小等可由 Host 观察；不能从自然语言“卡住了”或工具失败次数直接断言难题。重复动作须考虑输入/环境变化，合法复验不算无效重复。

这些信号用于决定何时整理当前假设、来源、排除理由与下一步，不用于强制每工具调用写长总结，也不用于替模型假定某条路线错误。

## 4. 推荐题型

优先选本地多阶段 Crypto 或小型静态 Reverse。简单识别题可用于 seed 快检，但不承担图板有效性证明。

| 题型 | 适合验证的行为 | 首轮条件 |
| --- | --- | --- |
| Crypto：参数约束识别 → 恢复密钥/中间量 → 二阶段解码/解密 | 条件核对、候选算法比较、中间值保留 | 小脚本能计算，输入可冻结，避免超预算大整数求解或随机碰撞 |
| Reverse：小型 ELF/脚本校验器，含多层变换或 dispatcher | 跨函数/分支关联、反例修正、候选输入验证 | 所需反汇编/运行能力已可用；提供固定架构环境 |
| Pwn：有源码/固定 libc 的本地堆题 | UAF/堆状态、地址关系、失败原因跨步骤保留 | 第二轮优先；先解决 OS/架构/进程交互环境，避免把工具缺失算记忆失败 |
| Web：可本地重置的有源码小应用 | 条件辨别与多步骤交互 | 可选第二轮；首轮不引入实例过期、平台限流与网络抖动 |

不优先选：一条 base64 即完成的签到题、主要靠长时间爆破的题、依赖重型 GUI/未知工具链的题、极端混淆且基线完全无进展的题，以及模型可能直接复述公开完整题解的著名原题。可以使用保留机制的变体，但变体需先验证可解，不能靠随机修改破坏原题。

## 5. 最小效果实验

先选一题做 4 次运行检查实验链路，再选两道代表题，每组各 3 次，共 24 次正式 attempt；预算和具体题目确定后再启动真实模型。该规模只用于先导方向判断，不足以做泛化收益结论。

| 组别 | 图板对模型的反馈 | seed |
| --- | --- | --- |
| A | 关闭 | 关闭 |
| B | 开启 | 关闭 |
| C | 关闭 | 开启 |
| D | 开启 | 开启 |

各组保留同样的审计、工具、基础任务/权限信息、模型设置、总预算、题目初态和验收。关闭图板反馈不等于删除日志/控制边界；关闭 seed 必须同时关闭自动注入和工具读回，不能仅 unset 显式 seed 文件。真实 prompt/工具定义是否发生其他差异须记录。模型不能通过目录/搜索工具读到另一组日志、完整 WP 或私有验收答案。

这四种独立实验模式尚未全部实现。现有 `full_history` 配置不能自动当作“无图板”组；在开关被实际 provider payload 验证前不启动付费对照。

本轮固定长会话或同样的轮换规则，避免把短会话收益混入图板效果。之后再单独做图板交接与普通有界摘要交接对照。学习晋升关闭，各次重置工作区、Session 和任务状态，使用同一知识快照、独立运行目录，随机/交错运行组别。

评估优先级：固定预算内成功率/阶段成功率 → 到首个独立有效进展和正确候选的耗时 → 无效重复与反例后的错误坚持 → token/模型请求/CLI 调用总量及图板维护成本。失败/超时不能从耗时统计中删掉，只比较成功样本可能产生偏差。

seed 单独记录：每个决策点应检索的主题/条件是否出现在库中、返回 top-3 是否命中适用段落、是否实际送入 provider 请求、后续行动是否用到、结果如何。检索命中/进入 RAM/模型说有帮助都不等于贡献；对照组比对才回答是否提高准确率和降低总耗时。任务答案/WP 由评估端保留，不放入模型知识库。

图板也区分结构/行为/结果：节点和引用正确、交接不丢状态属于结构；下一步使用已有进展、遇反例纠错、减少无效重复属于行为；成功率和成本收益属于结果。任一层失败应定位，不用更多节点数代表更强推理。
