# Aegis AI Agent 开发规范

状态：本次用户要求建立的开发规范。适用于 Aegis-owned 代码与测试；嵌入的 `Pi_Agent_base/pi/` 保持上游规范且本轮不修改。

## 1. 依据与适用方式

本规范采用常见的 Agent 工程做法：仓库级 `AGENTS.md` 入口、显式任务范围、小步变更、契约先行、测试先行、静态检查、代码审查、可复现交付。它不是某个行业标准认证，也不声称某框架使用率最高。

本地参考：

- `Pi_Agent_base/pi/AGENTS.md`：读取完整文件、核对真实 API 类型、限定 Git 操作、faux provider 测试、禁止隐式真实 API 调用。
- `Pi_Agent_base/aegis-biome.json`：Aegis 当前格式与 lint 规则。
- `docs/MEMORY_SCHEMA.md`、`docs/MEMORY_SCHEMA_NOTES.md`：证据与数据模型。
- `docs/ARCHITECTURE_DECISIONS.md`：已确认架构与用户授权。
- `docs/CAMPAIGN_ARCHITECTURE.md`、`docs/CAMPAIGN_CONTRACT_BASELINE.md`：Campaign 设计与收尾时的精确契约。
- `docs/AGENT_TESTING_STANDARD.md`：测试矩阵与运行证据。
- `docs/GIT_STANDARD.md`：分支、逐路径暂存、提交、纳管范围和历史保护；用户已授权使用本地 Git 管理开发。
- `docs/DS_ORCHESTRATION_WORKFLOW.md`：主 DS 拆分、子 DS 分发、审查和集成。

优先级：用户当前指令 > 已确认架构/数据契约 > 本规范 > 子任务说明 > 历史任务书。历史草案不能因为文件修改较新就覆盖已确认决定。发现冲突先记录具体字段/行为，不凭注释或测试作者的假设选边。

## 2. 工作分工

一次总委派允许主 DS 自主推进多个小任务。主 DS 必须先制定任务图和共同测试矩阵，之后按依赖执行；不是一口气把整个阶段写完再自测。

- 主 DS：完整理解架构、冻结接口、分配文件、维护共享测试计划、审查子任务、集成、运行阶段检查、提供最终材料。
- 测试任务：根据规格先生成正例、负例、组合例与可执行脚本；有条件时使用单独子 DS 会话。
- 实现任务：在指定文件范围内完成一个明确行为；不得自行改变共享契约或削弱冻结测试。
- 审查任务：针对最终 diff 和不变量检查问题；可以由一个未参与该模块编写的子 DS先审，主 DS必须再审。
- 用户/当前验收会话：决定架构变更与最终是否通过。

同模型子会话只能减少共享上下文偏差，不能证明错误独立。自审、子 DS 审查和全绿测试都不是外部验收的替代品。

## 3. 开始编码前的交付物

每个阶段先输出并保存：

1. 当前代码/测试基线：实际命令、退出码、已知失败。
2. 契约表：输入、输出、状态、信任来源、缺失字段行为、拒绝原因、幂等与恢复语义。
3. 任务依赖表：编号、范围、接口、测试、依赖和负责 DS。
4. 测试矩阵：`requirement_id -> case_id -> 预期行为 -> 测试脚本 -> 验证证据`。
5. 待决项：仅包含不能由现有用户授权解决的产品/架构问题。

采用既定契约、修复已观测缺陷、选择函数/文件名不需要每次请示。扩大授权、改变持久语义、降低证据门、新增真实 API/网络调用、修改 Pi 核心和新增依赖需要先核对已有授权；未授权部分停止，其余独立任务继续。

### 3.1 阶段范围冻结与推进（用户确认，适用于后续所有阶段）

阶段开始时冻结目标、必需验收项、明确不实现的能力与已知限制。实现者和审计者都遵守同一范围；不能每次发现边界问题就扩大当前阶段的硬门槛。阶段通过表示当前承诺成立，不表示系统完美或所有历史问题清零。

发现问题先判断当前可达路径、用户可见影响、是否破坏核心不变量，以及适合在哪一阶段处理：

| 处理类别 | 判断依据 | 执行方式 |
| --- | --- | --- |
| 当前阻塞 | 当前已实现路径可导致假成功、授权越界、重复副作用、预算错误或权威数据损坏，或使冻结的核心目标无法成立 | 用可复现证据说明影响，做最小修复及相关回归 |
| 当前非阻塞 | 问题真实但当前主路径影响有限，有明确运行限制或正确 fallback，不破坏本阶段核心承诺 | 可顺手小修；不为它单独延迟阶段交付 |
| 后置 / 后续阶段职责 | 性能优化、缓存加速、尚未接入的生命周期/适配器/UI/报告能力，或可在后续集成时合理处理 | 记录责任阶段、限制和重新评估条件，继续主线 |

严重度标签和阶段阻塞性分别记录，不能仅凭旧 P1 标签永久阻塞。后置不等于已修复，也不能假定后续会自动解决；必须保留问题与证据，在责任阶段显式复核。后续能力上线或运行方式改变，使风险进入当前可达路径时，重新判断。

冻结后新增阻塞项须说明具体复现、违反哪条当前核心承诺、为何不能安全后置。纯推测、风格偏好、测试数量、实现方式偏好或未实现的后续功能不足以重开阶段。必要安全/正确性缺陷仍可阻塞，不能为了进度隐瞒。

验收集中检查修复项和受影响路径，相关回归完成后不无理由重复扩大扫描。已知非阻塞/后置项不反复开新一轮外部审计；小修复复用现有计划和报告，更新证据与 Git 提交即可，不要求每次重建整套长文档。有限 mutation 与变更风险相称，不设小修复固定数量配额。

当前应用：C1 仅 F14 为剩余阻塞；F15 非阻塞、可顺手小修；F16 缓存优化后置。F14 聚焦验证和相关回归通过、完成限定外部复核后进入已获用户同意的 C2，不再因 F15/F16 重开 C1。该范围决定覆盖较早任务书的扩大要求，不允许自行声称外部已通过。

## 4. 模块和代码规范

### 4.1 复用当前技术栈

- 继续使用 Node ESM `.mjs` 和现有 TypeScript 扩展。不要为了统一样式重写已完成模块。
- 新公共接口用 JSDoc 或 TypeScript 明确类型，尤其 enum 值、可空字段、返回结果和信任上下文。
- 小型纯函数完成解析、准入、投影、聚合；文件/进程/Pi/网络操作放在明确的边界适配器。
- 复用已有 canonical/hash、EventLog、Board、Resolver、Broker；不再复制一套等价证据逻辑。
- 若需要改变旧接口，由主 DS 管理迁移和调用点测试；子 DS 不自行修改所有调用者。
- 行数不是目标。仅为了文件变短而拆成许多单行模块无助于正确性。

### 4.2 输入和状态

- 外部 JSON、模型输出、文件、HTTP 参数必须在进入状态机之前校验。
- 校验普通对象、数组元素、必需字段、状态值、有限且安全的整数、已知引用与权限范围。
- 不用 truthy 值代替合法状态或来源；未知 status 永远不能默认 success。
- 禁止将缺失 `scope`、目标或权限解释为通配符；也不要在无动作场景虚构权限。
- 返回可区分的失败类型和原因。`blocked`、`rejected`、`unknown`、`invalid`、调度失败各保留含义。
- 不保留用户未要求的兼容分支。已有明确同 major 兼容契约必须统一实现；不能一处接受一处拒绝。
- 规范化后的默认值必须真的出现在返回值，且不能改变原 Manifest 的授权语义。

### 4.3 证据、身份和引用

- UUID/前缀只能提供标识，不证明 Episode 独立性或 actor 可信。
- 来源可信度由受信任 Host/事件边界提供；模型在 JSON 中写 `source: oracle` 不获得判定权。
- 结构有效、引用存在、当前有效、判断可信是四个不同检查；不能只验证 ID 格式。
- Outcome 绑定 Campaign/Task/Episode/Stage/criterion/作用域；范围不匹配不能给当前任务发成功。
- correction、重新生成报告、重复 Session 都不是新独立证据。
- `unknown` 是有效判定状态，但不会形成 Fact。有效 Outcome 投影与 Fact 投影不能混为一张表。
- 数据获得、实际使用、阶段推进必须有对应引用；三个 truthy 字段不足以证明“有用”。

### 4.4 副作用与恢复

- 授权、最终参数、相关资源版本在 Broker 执行边界重新检查；UI 或工具列表不是授权边界。
- 可产生副作用之前，意图必须确认 durable。`append` 调用顺序或 Promise resolved 不等于 fsync 成功。
- 文件写入的 `wx`、原子 rename、fsync 分别解决不同问题，不要声称单个措施包办持久化。
- 副作用已可能发生但结果不明时先核对真实状态；不能以新 attempt/idempotency key 绕过停止规则。
- JSONL 是权威记录，checkpoint/UI/report 是派生物；篡改派生文件不能改变成功或授权。
- 错误不可用空 catch 隐藏。允许降级的辅助投影/UI失败应有诊断，不应暂停正常执行。

### 4.5 报告与敏感信息

- 报告以明确字段白名单构造，保留授权策略与证据引用，不复制 unrestricted raw output。
- 策略 enum 值按枚举恢复；禁止“先脱敏后恢复任意原值”。
- 精确记录缺失字段，不填零伪装已测量；成本、token 不可得时写 null/unknown。
- digest 只保证关联与完整性，不保证数据内容真实。每个 digest 定义覆盖字段和排除字段。
- 分享报告不分享 `auth.json`、完整凭据、flag 或原始私有会话。

## 5. 工作区和并行修改

- 不恢复根目录已删除 Python demo/AGENTS，不清理用户已有改动。按 `GIT_STANDARD.md` 在任务分支逐路径暂存并提交已授权的代码、测试和文档；禁止把历史“不提交”限制沿用到当前授权。
- 禁止 `git reset --hard`、`git clean -fd`、全局 checkout、stash，以及覆盖不属于本任务的未提交文件。
- 子 DS 各自拥有不重叠文件范围；共享接口文件、配置、index/export、文档由主 DS统一修改。
- 默认串行派发；若已有子 Agent 能力与独立工作区，可并行修改互不依赖文件。不要新造一套子 Agent 平台。
- 文件锁/隔离工作区只用于开发协作；不要把它与 Campaign 第一版单活动 Task/Episode 混淆。
- 在主 DS集成前，子 DS不得扩大 allowed paths 或更改其他任务的测试。

## 6. 检查规范

### 格式

复用 Aegis Biome，针对修改范围运行。不要把 Aegis 的检查配置扩散到 Pi monorepo，不降低 lint 规则来消除新增问题。

### 类型

现有 `tsconfig.aegis.json` 只覆盖旧 Batch E 模块，不能声称它检查了 Campaign。新增代码至少用 JSDoc 保留明确公共类型；主 DS应添加 Aegis-owned Campaign 类型检查配置或等价针对性检查，并报告覆盖路径和旧依赖错误基线。不能靠关闭检查、`any`、`@ts-ignore` 或排除本次代码得到绿灯。

### 测试

按 `AGENT_TESTING_STANDARD.md` 执行。先跑当前小任务，再跑受影响模块组合；阶段完成后一次运行所需回归。只有新改动或未解疑点才重复扩大测试，不用无限扫描替代设计。

### Pi 接口

进入 C2/C4a 时，完整读取实际使用的 Pi SDK/扩展文档和例子，并核对内嵌 Pi 的真实签名。不得凭记忆编造 `newSession`/tool hook 的参数。真实 Pi 测试使用 source resolver 和 faux provider；错误启动命令不构成环境失败证据。

## 7. 跨模块接线审查（当前 C1 收尾补充）

- 在矩阵记录具体产品入口/调用链。辅助函数单测通过不能标成Scheduler路径已接入。
- 不写死synthetic完成数量、admission数量或成功结论；计数由真实committed记录和产物计算。
- Claim外壳来自可信Runtime并不自动变可信Outcome；复用原Resolver/聚合，避免在新增projection写弱版本。
- 标为SHA256的摘要必须由现SHA256生成；不自写滚动hash替代，也不以注释说“dependency-free”作为新增算法理由。
- 开发辅助脚本批量改JSDoc/源码前保存私有基线，预览targeted diff；不使用不理解语法的正则改所有函数声明。若发生文件损坏，记录受影响文件并重新验证最终结构与行为。
- 一次开发任务允许跨模块集中修复已观测问题；不能删需求以缩小测试，也不能无限增加未观测的防御框架。

## 8. Definition of Done

一个小任务完成须满足：

- 契约项、对应正负测试和实际实现一一对应；
- 修复缺陷的测试在旧代码上确实失败，且失败原因符合预期；
- 冻结范围内没有未解决的当前阻塞项，没有通过削弱测试得到成功；非阻塞/后置项有明确记录，不要求全仓库问题清零；
- 主 DS已经阅读最终 diff 和关联调用点，并完成跨模块检查；
- 所需格式、类型、聚焦测试、集成和回归均有退出码与日志；
- 从权威输入重建派生物的结论没有依赖旧派生文件；
- 交付列明证明范围、尚未验证内容和外部验收状态；提供本地分支、commit id 与准确工作树状态。
- 审计发现的行为失败测试可提交为 red 基线，必须与缺陷报告关联。后置项保留原断言与真实结果，通过显式阶段测试清单区分；不删除、弱化或伪称通过，也不把它们自动当作当前阶段必需项。

主 DS可自主将通过内部检查的小任务集成到同一阶段；阶段是否可以进入下一阶段按总提示词的范围执行，不由子 DS自行决定。
