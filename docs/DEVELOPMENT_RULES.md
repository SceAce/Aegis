# 固定开发规则

由根 AGENTS.md 加载，适用于所有任务。这里只记录长期有效的协作和正确性原则。

## 任务与上下文

- 以当前用户目标确定范围；开始修改前确认目标、相关接口、验证方式和已有工作树状态。
- 用搜索定位后按需阅读。进入模块时加载其 AGENTS.md，不按历史阶段顺序通读所有任务书。
- 新接口或跨模块改动先写清职责、输入/输出、信任来源、持久化责任和受影响验证；小修复复用现有记录。
- 当前正确性问题与后置工作分别记录；不把目录整理、性能偏好或历史失败数量当作功能验收结论。
- 修改共享接口时同步调用点、导出、配置和必要文档；将代码放到实际职责目录。

## 正确性与信任

- 模型输出是提案。工具退出码、transport 成功或模型文本不能替代独立 Outcome、授权或预算结清。
- 外部输入在状态机/执行边界校验；缺失、冲突和未知不能静默解释为成功或通配授权。
- 副作用通过明确执行边界，执行前检查当前授权与最终参数，并确认意图已持久化。
- 可能已执行但结果未知时保留责任与证据，核对真实状态；不靠换 ID、重启或新 Session 绕过恢复约束。
- 权威日志和不可变输入与派生状态分开；checkpoint、缓存、报告和 UI 不能自行授予权限或制造成功。

## 工作区与权限

- 保留用户与其他任务的改动；不执行破坏性清理、全局恢复、强制覆盖或历史改写。
- 内嵌 Pi、凭据、真实网络/付费实验和新依赖等范围，先核对当前会话授权；旧文档的许可不能自动沿用。
- 不打印或提交凭据、私钥、完整私有会话或无限制原始输出。验证产物放 ignored 私有目录。
- 按现有本地 Git 规范在任务分支工作，显式暂存、审查后提交；不自动 push。详细操作按需见 [Git 规范](GIT_STANDARD.md)。

## 验证与交付

- 验证与变更风险相称：先聚焦，再检查受影响集成；文档修改检查链接与规则一致性，不为措辞新增业务测试。
- 保留有意义的断言；不靠删除、skip、放宽预期或关闭静态检查制造通过。
- 精确记录命令、真实退出码、已有基线与新回归。未运行、环境受限、已知失败和通过分别说明。
- 完成时给出实际变更、验证、剩余限制和 Git 状态。内部自测不等同于独立验收。

## 规则本身

- 根 AGENTS.md 只负责固定原则与加载；工程/模块规则按目录继承。
- 模块 AGENTS.md 写职责、边界、相关契约和验证入口，不保存阶段进度或历史工作流水账。
- 任务状态、临时范围、已知失败与复现放任务/审计文档，按需引用；归档仅作历史证据。
- 用户改变了约定时，同步当前规则，避免保留互相矛盾的有效要求。
