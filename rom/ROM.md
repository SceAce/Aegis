## 成果标准在公共黑板上

* 黑板上写着**用户需求**和**阶段任务** —— 那是"算不算成功"的**唯一依据**。
  开跑先读它：`aegis_board(action="read")`。
* **判成功不看工具退出码。** `ok=True` 只表示"命令没报错"，不表示"事情办成了"。
  实测差距极大：958 次动作里 931 次 `ok`，但真正拿到 root 的只有 2 轮。
  你要证明的是**黑板上的需求/任务被满足了**。
* 父 agent 把阶段拆成任务下派，子 agent 认领并回报；
  **agent 之间只能通过黑板通信**，没有别的信道。
* 核对是**机械**的：只认执行类工具输出里、行首原样打印出来的标记；
  读黑板/读文件里出现标记不算（那些地方本来就有 marker 原文）。
  `manual/<题>/TASK.md` 写了要打印的那几行，两条判据（强/弱）都在那里。
  **走弱判据时 harness 会审你的脚本** —— 所以利用脚本要留在工作目录里，别用完就删。

## 硬约束

1. **只有观测到的能驱动动作。** 不许为没发生的情况打补丁。
   需求由失败驱动，不由推测驱动。

2. **不许通过关闭保护来打通。** ASLR / NX / canary / RELRO / seccomp 是题目的条件，不是障碍。
   查看保护状态是允许的（观测是本系统要的东西）；**改动**会被工具层拒绝，
   而且那样拿到的 shell 不算数。

3. **不可逆禁止**：不删除工作区以外的文件；不停掉共享的执行环境。

4. **只碰当前题目。** `runs/`、`.aegis/`、`docs/`、`tests/`、`vendor/`、其它题目目录、
   `架构.md` / `框架.md` / `README.md` 都读不到 —— 工具层会拒绝。
   经验只通过上面的文档到达你，不通过历史记录。

5. **不许下载或搜索 Writeup。** 工具层会拒绝。做出观测、自己判断。

6. **被工具层拒绝就是硬拒绝**，不要换写法重试；按提示的替代方案走。

7. **一律用中文思考和交流。** 包括 **thinking / 推理过程**。
   你的思考过程会被人逐条审计，用中文才能被读懂 —— 英文思考等于没写。
   代码、命令、变量名、报错原文保持原样，不要翻译。
